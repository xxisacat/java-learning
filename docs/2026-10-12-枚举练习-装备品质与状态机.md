## 二、编程题 A：装备品质（带数据的枚举）

包：`src/enumtest/equip/`

**场景**：武器有品质，品质决定攻击力倍率 —— 游戏里最典型的「有限个值，每个值自带数据」。

### 需求

1. 枚举 `Quality`，三个常量，每个常量自带两个数据：

   | 常量 | 中文名 | 攻击倍率 |
   |---|---|---|
   | `COMMON` | 普通 | 1.0 |
   | `RARE` | 稀有 | 1.5 |
   | `EPIC` | 史诗 | 2.2 |

   - 字段、私有构造器、getter 自己写。

2. 类 `Weapon`：`name`（武器名）、`baseAtk`（基础攻击力，`int`）、`quality`（品质）。
   - `double realAtk()`：基础攻击力 × 品质倍率。

3. `EquipTest.main`：
   - 造三把武器并打印：新手木剑（10, COMMON）、烈焰大剑（40, RARE）、龙牙（60, EPIC）
   - 遍历 `Quality.values()`，打印品质一览

### 验收（跑出来长这样，数字对不上就是写错了）


## 三、编程题 B：玩家状态机（switch + 枚举）

包：`src/enumtest/state/`

**场景**：玩家的状态就那么几个，而且「能不能动、能不能打」是固定的 —— 枚举 + switch 的经典搭档。

### 需求

1. 枚举 `PlayerState`：`IDLE`（待机）、`RUNNING`（奔跑）、`ATTACKING`（攻击）、`HURT`（受击）、`DEAD`（阵亡）。
   - 这个枚举**不带数据**（和题 A 形成对照）：打印时直接打印枚举本身就行，Java 已经替它写好了 `toString()`。

2. 类 `Player`：`name`、`hp`（初始 100）、`state`（初始 IDLE）。

3. 查询方法（**必须用 switch 写**，感受一下 `case` 后面直接写常量名、不带类名前缀）：
   - `canMove()`：IDLE / RUNNING → true；其余 → false
   - `canAttack()`：IDLE / RUNNING → true；其余 → false

4. 动作方法：

   | 方法 | 规则 |
   |---|---|
   | `attack()` | 不能攻击（`canAttack()` 为 false）→ 打印「攻击失败：当前状态 XXX」，状态不变；能攻击 → 状态变 ATTACKING |
   | `hurt(int dmg)` | 已是 DEAD → 打印「XXX 已经阵亡」，hp 不变；否则 hp -= dmg，hp ≤ 0 → DEAD，不然 → HURT |
   | `recover()` | HURT → IDLE；其他状态 → 打印「现在不需要恢复」 |

5. `StateTest.main` 把下面七幕演完。格式自由，但每一幕都要能看出：**当前状态 + 能不能移动 + 能不能攻击**。

   ```
   ① 开局报告
   ② 挥剑            → 看状态
   ③ ATTACKING 里再挥一剑 → 应失败
   ④ 挨一刀（30 伤害）    → 看状态
   ⑤ 缓一缓（recover）    → 看状态
   ⑥ 挨致命一刀（100 伤害，此时 hp 只剩 70）→ 看状态
   ⑦ 死后挥剑、死后补刀   → 都该被挡住
   ```

### 一、概念题批改（2026-10-12，口头答）

**判定：Q3、Q5 干净 ✓；Q1、Q2、Q6、Q7 半对；Q4 未答（要求讲解）。**
本轮集中修正一句话：**「谁在什么时候干了什么」**。

| 题 | 他的答案（摘要） | 判定与修正 |
|---|---|---|
| Q1 | 「是一个对象，在编译的时候创建出来的」 | 对象 ✓；**时机 ✗**。编译期只查语法 + 生成 .class「图纸」，**造对象永远是运行时**；枚举常量在**类第一次被用到**时由 JVM 一口气全造好，只造一次（与静态字段同时机） |
| Q2 | 「可以创建无数个订单状态，并且也能随意修改」 | 半对。常量是 `final`，改不了。真坑两条：① **类型失守**——方法要状态，参数只能收 int，`setState(999)` 编得过；② **人看不懂**——打印出 1 / 2 / 3。一句话：**编译器帮不上忙** |
| Q3 | 跑出两条报错（Not a statement / Enum types cannot be instantiated）；「构造器 private，外界无法访问」 | ✅ 结论对。小修：① 不写 private 它也是 private（编译器强制）；② 不是「外界」，是**任何地方都不能 new**，实例只准在常量列表里造。【了解】报错文案随环境变：IDEA `Enum types cannot be instantiated` / javac 英文 `enum classes may not be instantiated` / 中文「无法实例化枚举类」——认关键词 **instantiate / 实例化** |
| Q4 | 未答，要求讲解 | `==` 比「是不是同一个对象」：自己和自己 → true（独一份），不同常量 → false。枚举**不用 equals 的特例**；对照：普通对象（String）不行、浮点也不行 |
| Q5 | values = 数组 ✓；valueOf「返回的是单个对象名」 | 小修：返回的是常量**对象**，名字是它的**参数**。报错贴对了——`IllegalArgumentException` 是**运行时**异常，编译期拦不住；valueOf 按名字**精确匹配**（大小写敏感） |
| Q6 | 半懂，「对象名没有指向 label」方向对 | 机制：`println(x)` = **替你调 `x.toString()`**；枚举的 `toString()` Java 默认写好 = **常量名**；`name()` 娘胎自带、终身变量名；`getLabel()` 是自己加的、**没人自动调**。想打印中文 → **重写 `toString()`**（加分题旁边那条路） |
| Q7 | 「不能」 | 第二问 ✓（隐式 final + 已隐式继承 `java.lang.Enum`）；第一问 ✗：**枚举能实现接口**（视频里就讲了） |

### 枚举最小记忆集（截至概念题；题 A / B 收官后定稿）

1. 【要背】枚举常量 = **类加载时造好的静态对象**，全 JVM 独一份 → 比较放心用 `==`
2. 【要背】编译期只查语法；「造对象」永远是**运行时**的事
3. 【要背】构造器私有（**编译器强制**）+ 实例只能在常量列表造 → 报错认 `instantiate / 实例化`
4. 【要背】不用枚举的坑 = **编译器帮不上忙**（类型失守 + 人看不懂）
5. 【要背】`println(对象)` = 替你调 `toString()`；枚举默认 `toString` = 常量名；`name()` 终身不变
6. 【要背】`values()` → 全部常量的数组；`valueOf("X")` → 按名字精确匹配，匹配不到是**运行时** `IllegalArgumentException`
7. 【要背】枚举**能实现接口**；不能被继承（隐式 final）

**报错速查（本轮实收）**

| 报错 | 真凶 |
|---|---|
| `无法实例化枚举类` / `enum classes may not be instantiated` / IDEA `Enum types cannot be instantiated` | 有人 `new` 了枚举 |
| `not a statement` | 光秃秃一个表达式当语句（new 完不接东西） |
| `IllegalArgumentException: No enum constant enumtest.OrderState.xxx` | `valueOf` 名字对不上（大小写敏感）；**运行时**才炸 |
| 打印出来是 `null` | `this.x = x` 两边名字没配对（自赋值），编译器零警告 |
