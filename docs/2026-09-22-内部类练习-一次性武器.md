## 这批题的由来

视频说「成员内部类 / 静态内部类 / 局部内部类没有匿名内部类重要」——这个判断是对的，但**对在哪**要你自己说出来（Q6 和编程题 B 就是干这个的）。

匿名内部类真正的价值只有一句话：**就地长出一个只用一次的实现。**
在你后面要做的东西里它无处不在——事件监听、回调、排序规则、线程任务，全是这个形状。今天把它练熟，等于提前拿到了后面好几个知识点的钥匙。

### Q6 三种内部类：写法与访问规则

```java
public class Outer {
    private int x = 10;

    class Inner {                 // ① 成员内部类
        void show() { System.out.println("Inner 看到 " + x); }
    }

    static class SInner {         // ② 静态内部类
        void show() { System.out.println("SInner 看到 " + x); }
    }

    void localDemo() {            // ③ 局部内部类

            void show() { System.out.println("Local 看到 " + x); }

        new Local().show();
    }
}
```

## 二、编程题 A：战斗系统（主菜）

包名 `src/innertest/battle/`

### 要写的类型

1. **接口 `Attackable`**：`int attack();` —— 返回这一次造成的伤害
2. **接口 `BattleListener`**：`void onHit(String target, int damage);` —— 有人挨打时被通知
3. **类 `Hero`**：`name` / `hp`（构造器给）+ `getName()` / `getHp()` / `isAlive()`（血 > 0）/ `takeDamage(int damage)`（扣血，扣到 0 就停在 0）
4. **类 `Arena`**（纯静态方法，不用 new）：

   ```java
   public static void duel(Hero a, Hero b, Attackable aWeapon, Attackable bWeapon, BattleListener[] listeners)
   ```

   契约：
   - 轮流出手：a 打 b → b 打 a → a 打 b ……
   - 任何一方 `isAlive()` 变成 false 就停
   - **每次有人挨打，就把数组里所有 listener 通知一遍**（伤害扣完了再通知）
   - ⚠️ `Arena` 里**一行具体武器/监听器都不许出现** —— 它只认接口（`SkillUtil` 那次的教训）

### Test.main 里的要求

**所有武器和监听器都用匿名内部类当场造**，不许为它们新开类文件：

- [ ] `Attackable sword`：每次固定 12 点
- [ ] `Attackable dagger`：**自己带一个字段**，初始 5，每攻击一次 +3（伤害序列 5 → 8 → 11 → 14 → 17 ……）
- [ ] `BattleListener logger`：打印 `[日志] XXX 受到 N 点伤害`
- [ ] 第二个监听器 `critWarn`：伤害 ≥ 15 时打印 `[警告] 暴击！`
      —— **这个不许单独存成变量，直接写在 `duel(...)` 的实参里**
- [ ] 用 `duel(...)` 打完一场，最后打印双方剩余血量和生还者

### 参考数字（可以改，但这两条必须成立）

双方 100 血、剑 12、匕首 5 起每次 +3。

1. **暴击警告至少触发一次**（数字对不上就自己调）
2. **账要对得上**：日志里某个人受到的伤害加起来 = 他掉的血。
   上次 `Iris's Current HP: 170` 那种「什么都没证明」的输出，这次不要再出现。
