## 这批题的由来

视频说「成员内部类 / 静态内部类 / 局部内部类没有匿名内部类重要」——这个判断是对的，但**对在哪**要你自己说出来（Q6 和编程题 B 就是干这个的）。

匿名内部类真正的价值只有一句话：**就地长出一个只用一次的实现。**
在你后面要做的东西里它无处不在——事件监听、回调、排序规则、线程任务，全是这个形状。今天把它练熟，等于提前拿到了后面好几个知识点的钥匙。

### 踩过的坑

#### 坑 1：返回值要表达「变了多少」，不是「现在是多少」（两幕）

**第一幕 —— 账对不上。** 原始输出里 `hero takes` 合计 124，但 hero 只掉了 100 血：

```
[LOG] hero takes 26 damage      ← 他只剩 2 点血，真实伤害就是 2，其余 24 点是打在尸体上的
```

`takeDamage` 用 `Math.max` 把血钳在 0，但交给 `onHit` 的仍是**原始伤害值** —— **监听器被告知了一个没发生过的伤害**。日志是给人看的证据，证据一旦撒谎，整套题就白做了。

改法：`takeDamage` 从 `void` 改成 `int`，返回 `before - after`（真实扣掉的血），`Arena` 把返回值交给 `onHit`。
为什么推荐"返回值"而不是"扣血前后读两次 `getHp()` 求差"：**改状态的操作要把真实结果交回调用方**（数据库 `update` 返回影响行数、RPC 返回实际处理条数，都是这个形状）；而且读两次状态，中间插了别的代码就会读错。

【要背】**改状态的操作，返回值要表达「变化量 delta」，不是「当前状态 state」。**

**第二幕 —— 修的时候把 state 当成了 delta。** 改 `Arena` 时接住了返回值，但 `takeDamage` 返回的是**剩余血量**（`return this.hp = ...`），于是日志变成：

```
[LOG] goblin takes 90 damage    ← 10 点的剑，第一刀不可能打掉 90
[WARN!] Critical hit!           ← 剩余血几乎都 ≥ 15，暴击一路刷屏
```

一个语义错，毒了两个监听器。两个自查手段，任何一个都能当场抓住它：

1. **量级检查**：10 点的剑第一刀报 90 —— 一眼假
2. **账要对**：报出去的数加起来必须等于掉血总量

【要背】改"怎么用"之前先看"怎么产生" —— **返回值的语义一变，方法体必须跟着变**，这是"改来改去"最常见的来源。

#### 坑 2：`isAlive` 的 if/else 白写 → 一行化时把条件弄丢了（不干活的语句，第 5 次）

```java
// 白写版
public boolean isAlive() {
    if (getHp() > 0) { return true; } else { return false; }
}

// 一行化途中写成（条件整个丢了）
public boolean isAlive() {
    return true;
}
```

第二版让 `Arena.duel` 的 `while (a.isAlive() && b.isAlive())` **永远成立** —— 实测刷到 `[LOG] hero takes 2903693 damage` 还在打，双方血量都被钳在 0，就是不死。

【要背】`if (条件) return true; else return false;` ≡ `return 条件;` —— **一行化时只有 if/else 两个词该消失，条件必须原样留下**。

#### 坑 3：用改名掩盖语义错（轻，但致命）

接口的契约是 `void onHit(String target, int damage)`，实现里把参数名改成了 `int real`：

```java
// Test.java 的匿名监听器
@Override
public void onHit(String target, int real) {        // ← 改名不解决语义问题
    System.out.println("[LOG] " + target + " takes " + real + " damage");
}
```

编译器不管（【了解】Java 的参数名不属于契约），但**名字从此开始撒谎** —— 叫 `real` 的时候，没人会去问"它真的是伤害吗"。改名是幌子，改语义才是修 bug。

#### 坑 4：日志字符串（不是错，但要知道边界）

题目写的是 `[日志] XXX 受到 N 点伤害`，交上来是 `[LOG] hero takes 10 damage`。**不必改回** —— 题目里写了"参考数字可以改"，但**具体字符串没写"可改"**。以后在真项目里，日志格式是给 grep 和监控看的，属于验收条件，别顺手换语言。

### 加餐：手写 `Fake` / `FakeArr` —— 手动重演 `val$` 捕获

（不在原题里。Q4 说破"捕获 = 复制一份存进字段"之后补的动手题）

初版写成了：

```java
public class Fake {
    final int[] hp = {100};
    public Fake() { }
    public int peek(int hp[]) {      // ← 每次现场问外面要，那就永远读到最新的值
        return hp[0];
    }
}
```

它恰好在演示「**没有复制**」是什么样 —— 所以当时预测"打印 200"是必然的，代码和预测是自洽的。

改成「字段只声明 + 构造器存值 + 无参 `peek`」之后，三段对照跑出：

```
Fake     -> 100     拷进去的是数字；外面改 hp = 200，里面看不见
FakeArr  -> 200     拷进去的是门牌号；arr[0] = 200 改的是对象，里面看得见
换门牌号 -> 100     arr2 = new int[]{200} 改的是变量，里面看不见
```

【要背】把这三个数字当口诀背 —— 它就是判据三问的三条分支：

1. 复制进去的是什么 —— **数字** 还是 **地址**？
2. 后来改的是 —— **变量** 还是 **变量指向的对象**？
3. 改变量 → 里面**看不见**；改对象 → 里面**看得见**。

补充（【了解】）：真实匿名内部类里，`hp = 200` 和 `arr2 = new int[]{200}` 这两行是**写不出来**的（javac 会拦住：必须是最终变量或实际上的最终变量）。手写这版等于拆了护栏的对照实验 —— 只有拆掉护栏，才能同时看到两个世界。

### 报错速查（本机 JDK 25 实测原文）

| 报错 | 含义 | 修法 |
|---|---|---|
| `错误: 可能尚未初始化变量val$hp` | 有 `final` 字段，但构造器没给它赋值（`hp = hp;` 也算没赋值） | 构造器里赋值一次：`this.val$hp = hp;` |
| `错误: 需要数组, 但找到int` | 在 `int` 类型的变量/字段上用了 `[0]` | 先确认这个名字当前是 `int` 还是 `int[]` |
| `错误: 类 X 是公共的, 应在名为 X.java 的文件中声明` | 两个 `public` 类塞进同一个文件 | 一个 `.java` 文件一个 public 类，且同名 |
| `错误: 从内部类引用的本地变量必须是最终变量或实际上的最终变量` | 真实匿名内部类里，事后改了被捕获的变量 | 让它 effectively final（或用字段/数组换个方式带值进去） |

表外还有一个**不报错**的：`a = a;`（参数自己赋给自己）—— 编译通过、字段永远保持默认值 0。这类只能靠「删了它会怎样」来查。

### 最小记忆集

1. **捕获 = 复制一份存进字段**（编译器的产物叫 `val$xxx`）；拷数字 vs 拷地址，决定里面看不看得见外面的改动
2. **改状态的操作，返回 delta 不返回 state**
3. **`if (条件) return true; else return false;` ≡ `return 条件;`** —— 一行化只删词，不删条件
4. **匿名 = 对源码匿名，对字节码一点都不匿名**（`Test$1` 就是它的真名，编号按源码出现顺序）
