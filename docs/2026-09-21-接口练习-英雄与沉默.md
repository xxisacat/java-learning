## 一、概念题（5 道）

### Q1 接口里的字段和构造器

```java
public interface Graph {
    double PI = 3.14;          // ①
    private String name;       // ②
    Graph(String name) { }     // ③
}
```

**答案：①②③ 三个都编译不过，`Graph.PI = 3.15;` 也过不去。**

| 写法 | javac 原话 | 原因 |
|---|---|---|
| `double PI = 3.14;` | `cannot assign a value to static final variable PI` | 接口字段隐式 `public static final`，**是常量**，赋值即改写常量 |
| `private String name;` | `= expected` | 接口里**不存在实例字段**，写什么修饰符它都只当常量处理，常量必须有初始值 |
| `Graph(String name) { }` | `<identifier> expected` | 接口**没有构造器**；编译器把它当成"方法忘了写返回类型"，于是开口要返回类型 |

`Circle implements Graph` 之后，原来那句 `super(name)` 的报错是：

```
error: constructor Object in class Object cannot be applied to given types;
  required: no arguments
  found:    String
```

`Graph` 变成接口后，`Circle` 的直接父类只剩 `Object`，`super(name)` 无处可去。

> **结论**：`extends` 改成 `implements`，丢掉的不是"一个关键字"，而是父类替你**存的状态**和替你**写的代码**。抽象类给"状态 + 实现 + 契约"，接口只给契约。

**批改：✅ 结论对，实验也真做了 —— 摔的这一跤比答对更值钱**

### Q2 一个对象能有几个类型

```java
Ppsportsman p = new Ppsportsman("Iris", 18);
Person person = p;           // ①
Sportsman sportsman = p;     // ②
Sayenglish english = p;      // ③
```

**答案：三行都合法。`speakEnglish()` 只有 ③ 能调，`learn()` 只有 ② 能调。**

**规则只有一条：变量能调用什么，100% 由它的声明类型上有什么方法决定，跟继承了几层无关。**

`Person` 上声明了 `getName()` / `getAge()` → 能调；没声明 `learn()` → 调不了（至于对象身上到底有没有 `learn()`，编译器不看）。

**批改：结论全对 ✅，但理由说成了「`Person` 与 `Ppsportsman` 中间隔着一个 `Sportsman`」—— 把 `Person` 摆成直接父类，`person.learn()` 照样编译不过。同一个 `p` 对象，透过三个窗口看过去，能看见的方法都不一样。**

### Q3 实现接口时最容易漏的 `public`

```java
public interface Swim { void swim(); }

public class Duck implements Swim {
    @Override
    void swim() { System.out.println("duck swimming"); }
}
```

**答案：编译不过。**

```
error: swim() in Duck cannot implement swim() in Swim
  attempting to assign weaker access privileges; was public
```

接口里 `void swim();` 的完整写法等价于 `public abstract void swim();`，两个修饰符都是隐式的：

- `public` —— 接口是**公开的契约**，实现时不能把可见性降下来（你写包私有就是"更弱"）
- `abstract` —— Java 8 之前接口方法全是抽象的（`default` / `static` / `private` 是后来的例外）

> 报错有两行时，**第二行通常是原因** —— 这里关键信息是 `weaker access privileges`。

**批改：结论对 ✅（贴了第一行，第二行是自己补跑出来的）**

### Q4 设计题：会飞的动物

> 鸟会飞；蝙蝠也会飞但蝙蝠是哺乳动物；企鹅、鸵鸟是鸟却不会飞。`fly()` 该放 `Animal` 还是做成接口？

**答案：接口 `Flyable`。**

- 企鹅/鸵鸟**是鸟却不会飞** → `fly()` 塞进 `Animal` 就是逼企鹅继承一个它没有的能力，只能写个空方法糊过去 —— **撒谎的代码**
- 蝙蝠**不是鸟却会飞** → 飞行能力跨越了整棵继承树

**批改：✅✅ 满分，是这套题最漂亮的一题 —— 两个事实各自论证了一个方向**

### Q5 设计题：`Person` / `Coach` / `SayEnglish` 三选

**答案：**

| 类型 | 结论 | 理由 |
|---|---|---|
| `Person` | 抽象类 | 手里有 `name` / `age` 状态 + 构造器 + getter/setter，接口装不下 |
| `Coach` | 抽象类（技术上能改成接口，**但不该**） | "教练是**一种人**"（is-a），还要靠 `super(name, age)` 共享 `Person` 的状态 |
| `SayEnglish` | 接口 | `PingpongCoach` 的 `extends` 后面已经站着 `Coach`，单继承的位置被占了，第二个身份只能靠 `implements` 挂上去 |

**判断一个类型该做哪个，问三句：**

1. 它要不要**存状态**？→ 抽象类
2. 它是"这一类东西的**共同身份**"（is-a）吗？→ 抽象类
3. 它是能挂到不同类族上去的**能力**（can-do）吗？→ 接口

**批改：⚠️ 半对 —— `Coach` 和 `SayEnglish` 的理由搅在一起了。另外 `sayEnglish` 是跨类族的（教练、运动员、以后还有裁判、队医），不是"乒乓球类独有"；真独有就不需要接口了。**

## 二、编程题：英雄与技能

包名 `interfacetest/hero/`。

### 要求

1. 抽象类 `Hero`：`name` / `hp` + 构造器 + getter/setter、`hurt(int)`（扣到 0 归 0）、`abstract void attack()`
2. 接口 `Healable.heal(int)`、`Talkable.talk()` —— **返回台词，打印是调用方的事**
3. `Warrior extends Hero`；`Priest extends Hero implements Healable`；`Bard extends Hero implements Healable, Talkable`
4. `SkillUtil`：`healAll(Healable[], int)`、`showTalks(Talkable[])` —— **零 `instanceof`**
5. `Test`：≥4 个角色，先掉血 → `Healable[]` 治疗 → **同一个 Bard** 进 `Talkable[]` → `Hero[]` 多态 `attack()`
6. **沉默技能**：`silence(Talkable t)` —— 沉默后该角色 `talk()` 返回 `"..."`
7. **（原理题）** 一个 Bard 同时进 `Healable[]` 和 `Talkable[]`，内存里是**几个对象**？

### 提交结果

```

Iris received 70 points of damage. Current HP: 100
Snow can attack the other party with a sword
Wind can attack the other party with a sword
Morning can attack the other party with a staff
Iris can attack the other party with a guitar
Morning heals for 20 HP
Morning's Current HP: 90
Iris heals for 20 HP
Iris's Current HP: 120        ← 100 + 20，账对得上
Iris: Hello! Can you hear me? ← 沉默前
Iris: ...                     ← 沉默后
true                          ← healers[1] == talkables[0]
```

### 做对的地方

- **沉默的设计完全正确**：状态放类里（`Bard.silenced`）、契约进接口（`Talkable.setSilenced`）—— 这是唯一的正路
- `healAll` / `showTalks` 参数全是**接口类型**，一行 `instanceof` 都没有
- 同一个 `b1` 同时进 3 个数组（`Healable[]` / `Talkable[]` / `Hero[]`），并自己加了 `healers[1] == talkables[0]` 打印 `true` —— "输出当证据"的正确用法
- `hp = Math.max(0, hp - damage)`、`Math.min(hp + amount, maxHp)` 都用上了
- `maxHp` 是题目没要求、自己加的，而且真用在了封顶上

### 踩过的坑

#### 坑 1：覆写父类方法，改了语义

```java
// Warrior：想表达"战士不能加血"
@Override
public void addHp(int amount) {
    setHp(amount);        // ← setHp 是「设为」，不是「加上」
    System.out.println(getName() + " Can't add HP");
}
```

`setHp(amount)` 把血量**设成** `amount`：300 血的 Yang Yang 被调一次 `addHp(20)`，血量变成 **20**。一个想"挡掉加血"的方法，成了最狠的一刀。它没被调用过（Warrior 不挂 `Healable`），所以一直没暴露。

**覆写可以改行为，不能改承诺。** `Hero.addHp` 承诺"加血"，覆写后变成"设血"，以后 `Hero h = warrior; h.addHp(20);` 谁也看不出这里会出事。

同时暴露了第二个问题：`Hero.setHp` 是个**后门** —— public 的 setter 能 `setHp(99999)`，绕过刚写好的 `maxHp` 上限。删掉 `addHp` 和 `setHp`，两个问题一起消失。

#### 坑 2：沉默撞的墙 —— 引用类型决定能调什么（同一条规则第 3 次出现）

```java
public static void silence(Talkable t) {
    t.setSilenced(true);     // ← 但 Talkable 上还没有这个方法时：
}
```

```
错误: 找不到符号
  符号:   方法 setSilenced(boolean)
  位置: 类型为Talkable的变量 t
```

**接口没有状态**（Q1 已经证明），所以 `silenced` 只能放类里；而 `t` 的声明类型是 `Talkable`，透过这个窗口**看不见** Bard 里的任何字段 —— 于是"想通过接口改状态，就必须把动作写进契约"。

**三步分工（记住这一句）：**

> **契约在接口（`setSilenced`）、状态在类（`Bard.silenced`）、写入靠 `SkillUtil`、判断在 `talk()` 里那句 `if`。**

顺带堵死两条岔路：`default` 救不了（default 也没地方存状态）；参数改成 `Hero` 或强转能跑，但那样 `Talkable` 就成摆设了。

#### 坑 3：返回值不是输出（不干活的语句，第 4 次）

```java
SkillUtil.silence(b1);
b1.talk();          // ← 返回的字符串没人接、没人打印，直接进垃圾桶
```

现象是"沉默跑出来了，但屏幕上什么都没有"。`talk()` 是**返回**台词，打印是调用方的事 —— 所以要么 `System.out.println(b1.talk())`，要么再来一次 `SkillUtil.showTalks(talkables)`（对照更清楚）。

#### 坑 4：满血治疗 —— 输出没有证据力

```
Iris heals for 20 HP
Iris's Current HP: 170      ← 治疗前也是 170，数字根本没动
```

Iris 是 `170/170` 满血，`Math.min` 顶到上限，这条输出证明不了 `heal` 干过活。补一句 `b1.hurt(70)` 之后：`100 → 120`，**账对得上，输出才成为证据**。

#### 坑 5：原理题 —— 不是"两个对象"

**正确账目：**

- 对象：`new Bard(...)` 造了 **1 个**；`Healable[]` / `Talkable[]` / `Hero[]` 各自是堆上的**独立对象**（数组也是对象）
- Bard 的地址：**1 个**
- 写着这个地址的**纸条（引用）**：多张 —— `b1` 在 `main` 的**栈帧**里，`healers[1]` / `talkables[0]` / `heroes[3]` 在**堆**上的数组格子里

**引用 = 写着地址的纸条。** 抄多少张纸条都不产生新对象；透过哪个窗口看，看到的是同一份字段。

## 三、这套题真正学到的

1. **对象只有一个，类型是看它的角度。**
   引用类型决定"能调用什么"（Q2 的 `person.learn()` 编译不过、坑 2 的 `setSilenced` 找不到符号、Q5 的 `SayEnglish` 必须挂上去）—— 这是本套题里咬人最多的一条规则。

2. **接口只给契约：不给状态，也不给实现。**
   状态在类里（坑 2），实现会重复（`Priest.heal` 和 `Bard.heal` 一模一样，`default` 也救不了 —— 它打不出名字，因为看不见 `name`）—— **重复是接口的代价**，不是写错了。

3. **每条语句问一句「删了它会怎样」，每段输出问一句「它证明得了什么」。**
   不干活的语句不会报错（坑 3），没证据的输出也看不出错（坑 4）—— 两者都是"程序在撒谎"。
