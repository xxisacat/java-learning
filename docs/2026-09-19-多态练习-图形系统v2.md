## 一、概念题（5 道）

### Q1 字段 vs 方法

```java
class A {
    String name = "A";
    String getName() { return name; }
}
class B extends A {
    String name = "B";
    String getName() { return name; }
}

A a = new B();
System.out.println(a.name);
System.out.println(a.getName());
```

**答案：第一行 `A`，第二行 `B`**

- `a.name` —— **字段没有多态**。看 `a` 的**编译时类型**（`A`），取到 `A.name` → `A`
- `a.getName()` —— **实例方法有多态**。看对象的**运行时类型**（`B`）→ `B.getName()` → `B`

**批改：✅ 正确**

### Q2 静态方法

```java
class A {
    static void hello() { System.out.println("A"); }
}
class B extends A {
    static void hello() { System.out.println("B"); }
}

A a = new B();
a.hello();
```

**答案：输出 `A`**（不是 `B`）

**静态方法没有多态。** 编译器看到 `a` 的**声明类型**是 `A`，编译时就把 `A.hello()` 写死进字节码，运行时的对象是谁它压根不看。

两个佐证：

- 不创建对象也能调：`A.hello();` 一样输出 `A` —— 说明 `new B()` 那一下在本题里完全是白 new 的
- IDEA 会对 `a.hello()` 画黄警告：*static member accessed via instance reference*，正确写法是 `A.hello()`

> 对比 Q1 第二行：同一个 `a`，`a.name`/`a.hello()` 是**编译时**定，`a.getName()` 是**运行时**定。

**批改：❌ 答成 `B` —— 这题错得值钱，补上了一个盲区**

### Q3 没有抽象方法的抽象类

```java
public abstract class Animal {
    public void sleep() { System.out.println("sleeping"); }
}
```

**答案：① 能编译 ② 不能 `new Animal()` ③ 有意义**

方向性是单向的：

- 有抽象方法 → 类**必须** `abstract`（这个方向强制）
- 类标了 `abstract` → **不要求**必须有抽象方法

`abstract` 的本职工作是**禁止 `new`**。一个方法都不抽象，照样禁止。用途是「这个类本身没有意义，只允许被继承」—— 你不会想要一个"动物"对象，只会想要具体的猫和狗。

**批改：①❌ 答成"不能编译" ②✅ ③✅（理由说对了）**

### Q4 向下强转

```java
Animal a = new Cat();
Dog d = (Dog) a;
```

**答案：① 编译能过 ② 运行时抛 `ClassCastException` ③ 编译器只看「类型上可能不可能」**

编译器**只看声明类型**：`a` 是 `Animal`，而 `Dog` 是 `Animal` 的**子类** —— "这个引用有可能真指向一条狗"，类型上可能成立，于是放行，同时插入一条运行时的类型检查（`checkcast`）。运行时 JVM 看对象的**真实类型**（`Cat`），不是 `Dog` → 抛异常。

**证明编译器确实在检查**：把 `Dog` 换成毫无继承关系的类，编译直接失败。

```java
String s = (String) a;   // 编译错误：incompatible types
```

**批改：①②✅ ③ 方向对（"编译时视作 Animal 类"），需补上"所以它无法知道 new 的到底是谁，只能留到运行时查"**

### Q5 设计题（无代码）

> 如果 `Graph` 不声明 `getArea()` / `getPerimeter()`，只让 `Circle` / `Rectangle` 各自定义，`Student.learnGraph(Graph graph)` 还能写成 `graph.getArea()` 吗？

**答案：不能。**

**引用类型决定了"能调用什么"。** 编译器拿 `graph` 的声明类型 `Graph` 去查方法表，`Graph` 上没有 `getArea()` → 编译直接过不去。那两个方法只能算两个子类各自的独有方法。

**批改：✅ 完全正确，说得很准**

## 二、编程题：图形系统 v2

包名 `polymorphic.shapev2`。

### 要求

**1. 抽象类 `Shape`**

- `private String name`，构造器 `Shape(String name)` + getter
- `public abstract double area();`
- `public abstract String describe();` —— **返回字符串，不要在里面打印**
- `public void printInfo()` —— 普通方法，内部打印 `describe()` 和 `area()` 的结果

**2. 三个子类**，全部加 `@Override`

- `Circle` —— 半径
- `Rectangle` —— 长、宽
- `Triangle` —— 底、高

**3. `Circle` 加一个静态计数器**

- `private static int count;` + `public static int getCount();`
- 每创建一个 `Circle`，`count` 加 1
- 💡 提示：`Circle` 有几个构造器？**只在一个里加会怎样？**

**4. `ShapeUtil` 类**，一个方法 `public void printAll(Shape[] shapes)`

遍历数组，对每个元素调用 `printInfo()`。**一行 `instanceof` 都不许有。**

**5. `Test`**

- 建一个 `Shape[]`，装至少 4 个图形（≥2 个圆、1 个长方形、1 个三角形）
- 调 `printAll()` 打印全部
- 最后打印 `Circle.getCount()`，确认数量对

### 加分题

**6.** `Triangle` 加独有方法 `boolean isRightTriangle()`；在 `Test` 里遍历数组时，**只对三角形**打印「这是直角三角形」—— 这一处**必须**用 `instanceof` + 强转。

> 对比：第 4 题**不许**判断，第 6 题**必须**判断。差别在哪？

**7.（原理题）** `Shape.printInfo()` 写在父类里，内部调用的 `describe()` 是抽象方法。运行时调到的是哪个 `describe()`？

> 📌 **出题的坑**：第 6 题的 `Triangle` 原本只有底和高，**两条边判不了直角三角形**（需要三条边）。后来补了 `side3` 字段作为补丁，所以题目原文和最终代码在这里有出入。

### 提交结果

```

Area is 200.96 and describe is This circle's r is 8.0
Area is 48.0 and describe is This rectangle's length is 8.0 and width is 6.0
Area is 24.0 and describe is This triangle's base is 8.0 and height is 6.0
t is a right triangle
2
```

### 做对的地方

- **`count` 加在了两个构造器里** —— 这是第 3 题提示的坑，用哪个构造器创建都算数，`getCount()` 输出 2 正确
- **`printAll` 保持零 `instanceof`** —— 纯多态遍历
- **`describe()` 是 `return` 字符串，不是在里面打印**
- **`isRightTriangle()` 用 `Math.abs(...) < 1e-6`** —— 浮点数不能用 `==`
- **Q7 答对了**：`describe()` 调到的是子类重写的那个，和 Q2（静态方法输出 A）正好是一对反例

### 踩过的坑

#### 坑 1：写了一条不干活的语句

```java
String[] Shape = {"c1", "c2", "r", "t"};   // ← 从没被用到（已删）
t.isRightTriangle();                       // ← 算了结果直接扔，紧接着又算一遍（已删）
```

同一个毛病出现了三次（另外一次是 `eat(String something)` 参数没用到）。**排查习惯**：每条语句问一句「删了它会怎样」，删了没区别的，就是它。

另外 `String[] Shape` 这个变量名**大写开头，跟类名 `Shape` 撞了**。Java 里类型名和变量名是两个命名空间，所以能编译 —— 正因如此更危险，报错时你会看不懂。**变量名一律小驼峰。**

#### 坑 2：`instanceof` 放错了地方

一开始把判断写进了 `ShapeUtil.printAll()`，而题目明令禁止。

**为什么不能用 `printAll` 判**：

- `printAll` 的职责是「给我什么形状都能打印」，对每个元素**一视同仁** —— `printInfo()` 是父类声明的方法，多态会自动找到正确的实现
- `isRightTriangle()` 是**三角形独有**的东西，对一个圆问「你是不是直角三角形」没有意义。这种「只针对某个子类的需求」是**调用方**的需求

**代价**：以后加个五边形，`printAll` 本来一行都不用改。塞进三角形判断之后，它就不再是"通用打印"了 —— 每来一个"只对这个形状才做的事"就长一段，最后变成几十行互相耦合的 if-else 怪物。**这正是多态要消灭的东西。**

正确位置是 `Test`：

```java
util.printAll(shapes);
for (int i = 0; i < shapes.length; i++) {
    if (shapes[i] instanceof Triangle) {
        Triangle t = (Triangle) shapes[i];
        if (t.isRightTriangle()) {
            System.out.println(t.getName() + " is a right triangle");
        }
    }
}
```

> ⚠️ 这处错误**编译通过、输出也完全正确**（跟 `eat()` 那次一样）。编译器不报、输出看不出来，只能用「职责」这把尺子量。

#### 坑 3：浮点数的证据来自自己的输出

```
Area is 113.03999999999999        ← 3.14 × 36，本该是 113.04
```

`double` 存不下精确值（`0.1 + 0.2 != 0.3` 同理），所以比较要用「**差得足够小**」：

```java
public boolean isRightTriangle() {
    return Math.abs(base * base + height * height - side3 * side3) < 1e-6;
}
```

## 三、这套题真正学到的

1. **编译时类型决定「能调用什么」，运行时类型决定「调到谁的」。**
   Q1（字段只看前者）、Q2（静态只看前者）、Q4（强转就是让编译器放行、运行时再查）、Q5（父类没声明就调不了）—— 四道题是同一条规则的不同侧面。

2. **所有子类一视同仁的逻辑 → 放父类 / 工具类，靠多态；只针对某一个子类的特殊逻辑 → 放调用方，用 `instanceof` + 强转。**
   第 4 题不许判断、第 6 题必须判断，差别就在这句话。

3. **每条语句问一句「删了它会怎样」。**
   不干活的语句不会报错，只会让代码撒谎。
